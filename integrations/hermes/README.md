# VibeLamp как индикатор состояния Hermes Agent

Мост «агент → лампа»: пока Hermes думает, светильник пульсирует; пока копается
в терминале — бежит голубая волна; когда просит внимания — мигает жёлтым.

Состоит из двух частей, и это разделение принципиальное:

| Часть | Где живёт | Что делает |
| :-- | :-- | :-- |
| `hermes_plugin/` | `~/.hermes/plugins/vibelamp-status/` | подписывается на хуки Hermes и пишет по строке на событие в spool |
| `lampd.py` | отдельный процесс | единственный владелец USB-порта, читает spool и рисует состояние |

Плагин **не трогает железо**. Если бы он держал порт из процесса шлюза, любая
заминка с USB тормозила бы агента. Поэтому плагин только пишет файл, а светом
занимается демон.

## Установка

Нужны: Hermes Agent, светильник VibeLamp в USB, Python 3.9+.

```bash
python integrations/hermes/install.py
```

Скрипт:

1. копирует плагин в `~/.hermes/plugins/vibelamp-status/`;
2. включает его (`hermes plugins enable vibelamp-status`);
3. создаёт отдельное окружение `~/.vibelamp/venv` и ставит туда `vibelamp`
   из этого чекаута (вместе с `pyserial`);
4. регистрирует демон как пользовательский сервис: launchd на macOS,
   systemd --user на Linux.

После установки перезапустите шлюз Hermes — плагины загружаются при старте:

```bash
hermes gateway restart
```

Полезные флаги: `--dry-run` (только показать план), `--no-service` (разложить
файлы, сервис не регистрировать), `--uninstall` (убрать всё установленное).

## Палитра

| Состояние агента | Что видно | Значения |
| :-- | :-- | :-- |
| пришло сообщение | белая вспышка | `rgb 255 255 255`, 0.35 с |
| думает | алый пульс `#FF2400` | `breathe 2000`, яркость 170 |
| зовёт инструмент | голубая бегущая волна | `running 900 0 200 255` |
| задаёт вопрос (`clarify`) | жёлтое мигание | `blink 900` цветом `#FFD228` |
| завершил ход | зелёная вспышка `#00CC00` | `rgb 0 204 0`, 3 с |
| ждёт сообщения | зелёное дыхание `#009900` | `breathe 4000` |
| тишина дольше 3 минут | редкое дыхание | `breathe 20000`, яркость 70 |
| ошибка инструмента | красная сирена | `blink 220`, 3 с |

Оттенки и длительности — константы в `lampd.py` (`STATES` и блок ниже), их
можно править под свой вкус. Порог «редкого дыхания» переопределяется
переменной окружения `VIBELAMP_IDLE_AFTER` (секунды).

### Почему волна, а не мигание на каждый вызов

Первый вариант светил голубым на каждый инструмент — и на бойком ходе лампа
превращалась в стробоскоп: голубой, алый, голубой, алый. Поэтому голубое
состояние включается по двум правилам: для заведомо долгих инструментов
(браузер, сеть, делегирование — список `HEAVY_TOOLS`) сразу, для остальных
только если вызов тянется дольше секунды (`TOOL_SHOW_AFTER`). Гаснет оно с
задержкой `TOOL_HOLD_AFTER` (1.5 с), чтобы серия быстрых вызовов читалась как
один блок. Мгновенные чтения файлов глазом не видны — они сливаются в ровное
«работаю».

## Как это работает

```
Hermes (turn_start, pre_tool_call, post_llm_call, ...)
        │  хуки плагина
        ▼
~/.vibelamp/events.jsonl          по одному JSON на строку
        │  tail
        ▼
lampd.py  ── Engine (событие → состояние) ── Painter (SDK) ── USB CDC
```

События, которые плагин публикует: `turn_start`, `thinking`, `api_done`,
`tool_start`, `tool_end`, `turn_end`, `error`.

Пока плагин не загружен (например, шлюз ещё не перезапускали), демон читает
собственный лог Hermes `~/.hermes/logs/agent.log` — грубее: без имён
инструментов и без их старта, только начало и конец хода. Как только плагин
оживает, приоритет у него.

## Отладка

```bash
# прогнать всю палитру на устройстве и выйти
~/.vibelamp/venv/bin/python integrations/hermes/lampd.py --test

# запустить демон на переднем плане с логом
~/.vibelamp/venv/bin/python integrations/hermes/lampd.py --verbose

# что видит демон
tail -f ~/.vibelamp/lampd.log
```

Если лампа не реагирует:

* порт держит кто-то другой — запущенный демон, другое приложение, старый
  процесс. Порт эксклюзивный, владелец должен быть один;
* устройство не найдено — проверьте `vibelamp.scan()` и `vibelamp.diagnose()`;
* на Linux нет прав на `/dev/ttyACM*` — см. udev-правила в документации SDK;
* события не идут — `tail -f ~/.vibelamp/events.jsonl`: файл должен пополняться
  на каждом ходе. Пусто значит плагин не загружен: перезапустите шлюз и
  проверьте `hermes plugins list`.

## Ограничения

* Поддерживаются macOS и Linux как сервис; на Windows `install.py` разложит
  файлы и подскажет команду ручного запуска (регистрация сервиса не
  реализована).
* Демон рассчитан на один светильник.
* Интеграция использует только публичный API SDK — `Lamp`, `Effect` — и не
  требует изменений в ядре библиотеки.
